# Email activity API

Records on the timeline of a lead or contact that an email was **opened in
Gmail** for it. The server sends nothing and cannot know whether the user
pressed Send: the browser opens a prefilled Gmail compose tab (see
`docs/mail-recipients-api.md`) and then calls this endpoint so each record's
timeline shows that an email was started.

```
POST /api/email-activity/compose/
```

Permissions: `IsAuthenticated` + `IsCompanyUser`. The company and the actor
always come from the signed-in user (the token). `company_id`, `actor` or any
similar field in the body is ignored.

## Wording: "opened", not "sent"

The timeline message is `Email opened in Gmail by <actor name>` and the event
type is `EMAIL_COMPOSED`. A Gmail compose tab can be closed, edited, saved as a
draft or sent to someone else; the CRM cannot tell. Words such as "sent" or
"delivered" would be false, so they are never used, in the message, the event
type or the metadata.

## Request

```json
{
  "client_ref": "3f0c2d3e-8a43-4a4b-9a77-0b5d6f3a9c11",
  "channel": "GMAIL_COMPOSE",
  "targets": [
    {"record_type": "CONTACT", "record_id": "<uuid>"},
    {"record_type": "LEAD", "record_id": "<uuid>"}
  ],
  "subject": "Quarterly check-in",
  "batch_index": 1,
  "batch_total": 3
}
```

| Field | Rules |
|-------|-------|
| `client_ref` | required; a UUID generated by the frontend **once per compose action** (not per request attempt). Stored in lower case, so the spelling does not matter |
| `channel` | required; only `GMAIL_COMPOSE` today (an enum, more can be added) |
| `targets` | required; 1 to **50** entries, counted as sent. Each is `{"record_type": "CONTACT" or "LEAD", "record_id": "<uuid>"}`. Repeated entries are collapsed |
| `subject` | optional string or null. Trimmed, control characters replaced by a space, **truncated** (not rejected) to 200 characters; empty becomes `null` |
| `batch_index`, `batch_total` | optional positive whole numbers, each on its own; `batch_index` must not be greater than `batch_total` when both are sent |

## Response

```json
{"logged": 3, "already_logged": 0, "not_found": []}
```

| Status | When |
|--------|------|
| `201` | at least one new event was written |
| `200` | nothing new was written: everything was already logged (a retry), or no target was found |
| `400` | invalid input, `{"detail": "..."}` |
| `401` | not authenticated |
| `403` | not a company user (platform superadmin, inactive user, suspended company) |

* `logged`: events written by this request.
* `already_logged`: targets that already had an event with this `client_ref`.
* `not_found`: targets that do not exist, are soft-deleted or belong to
  another company, as `{"record_type": "...", "record_id": "<uuid>"}`. The
  response never says which of the three it is. The other targets are still
  logged.

## What is written

**One event per target**, never one shared event, so a record's timeline never
shows the other recipients of the same compose action. The event is read with
the existing `GET /api/timeline/leads/<id>/` and
`GET /api/timeline/contacts/<id>/`:

```json
{
  "id": "<uuid>",
  "event_type": "EMAIL_COMPOSED",
  "actor": {"id": "<uuid>", "name": "Admin One"},
  "message": "Email opened in Gmail by Admin One",
  "metadata": {
    "client_ref": "3f0c2d3e-8a43-4a4b-9a77-0b5d6f3a9c11",
    "channel": "GMAIL_COMPOSE",
    "subject": "Quarterly check-in",
    "recipient_email": "ann@example.com",
    "batch_index": 1,
    "batch_total": 3
  },
  "created_at": "...",
  "targets": [{"entity_type": "CONTACT", "entity_id": "<uuid>"}]
}
```

`recipient_email` is that record's **own** email at that moment (`null` when
it has none); it is not validated, because the event only records what the
user was shown. Every metadata key is always present (`null` when not sent).
The message is at most 500 characters.

All valid targets are written in one database transaction (the project's
`DjangoTransactionManager`): either all of them or none.

## Idempotency

The same `client_ref` never creates a second event for the same target. Before
writing, one query asks the timeline which of the targets already have an
`EMAIL_COMPOSED` event with `metadata.client_ref = <client_ref>` (company
scoped, soft-deleted events ignored). So a frontend retry, a double click or a
network replay is harmless:

```
POST ... client_ref=A, targets [x, y]   -> 201 {"logged": 2, "already_logged": 0, ...}
POST ... client_ref=A, targets [x, y]   -> 200 {"logged": 0, "already_logged": 2, ...}
POST ... client_ref=A, targets [x, y, z] -> 201 {"logged": 1, "already_logged": 2, ...}
POST ... client_ref=B, targets [x, y]   -> 201 {"logged": 2, ...}   (a new compose action)
```

Limit: this is a lookup before the insert, not a database constraint. Two
requests with the same `client_ref` that arrive at the very same instant can
both pass the lookup. The frontend sends one request per compose action and
retries only after a failure, so this is accepted.

## Who may log against what

A user may log against every record they may open, mirroring the read rules
that exist today:

* **Contacts:** every company user (list and detail views have no role check).
* **Leads:** every company user. The lead *list* is admin-only
  (`LeadPermissions.can_view_all_leads`), but the lead *detail* view has no role
  check, and an id-based action opens specific records, exactly like the
  `mailing` module's `ids` selection. Records of another company are
  `not_found`, whatever the role.

Converted leads can still be logged against (their detail and timeline stay
readable).

## Errors (`400`)

| Cause | `detail` (example) |
|-------|--------------------|
| no targets | `targets must contain at least one target.` |
| more than 50 targets | `targets cannot contain more than 50 entries.` |
| bad channel | `channel must be one of: GMAIL_COMPOSE.` |
| bad `client_ref` | `client_ref must be a valid UUID.` |
| bad target | `targets[0].record_type must be one of: CONTACT, LEAD.` / `targets[0].record_id must be a valid UUID.` |
| bad batch | `batch_index cannot be greater than batch_total.` / `batch_total must be a positive whole number.` |
| missing field | `client_ref: This field is required.` |

Nothing is written when the request is refused.

```
POST /api/email-activity/compose/
Authorization: Bearer <token>

{"client_ref": "3f0c2d3e-8a43-4a4b-9a77-0b5d6f3a9c11",
 "channel": "GMAIL_COMPOSE",
 "targets": [{"record_type": "CONTACT", "record_id": "<ann>"},
             {"record_type": "LEAD", "record_id": "<lee>"},
             {"record_type": "CONTACT", "record_id": "<somebody in another company>"}]}

201
{"logged": 2, "already_logged": 0,
 "not_found": [{"record_type": "CONTACT", "record_id": "<somebody in another company>"}]}
```
